# 前端选品台（Frontend Selection Board）

一个专门给 AI 用的、本地运行的"前端选品台"：把前端需求拆成可选的模块与风格，让不懂前端的客户像在 4S 店选配汽车一样，通过拖拽和可视化预览 DIY 自己的页面，最终导出一份结构化配置单交给 AI（Codex），约束 AI 只做"按单组装"，减少无谓思考和 token 消耗。

## 核心思路

```
客户（不懂前端，只会说"我想要个好看的官网"）
   │  点选 / 拖拽模块 + 风格
   ▼
┌─────────────┐
│   选品台 UI  │  ← 菜单式分类 + 实时可视化预览
└──────┬──────┘
       │ 输出
       ▼
┌─────────────┐
│  配置单 Spec │  ← 结构化、紧凑、无歧义（spec.json + spec.md）
└──────┬──────┘
       │ 作为上下文注入
       ▼
┌─────────────┐
│  AI（Codex） │  ← 只在约束内组装，不自由发挥
└──────┬──────┘
       ▼
   前端项目成品
```

本质是一个"人类意图 → AI 约束"的翻译层：把模糊的口语需求收敛成一份无歧义的配置单，前端消化掉需求熵，AI 从"开放式创作"降级为"约束式组装"。

## 目录结构

```
前端网页设计流/
├── prototype-v1/     # 第一版最小闭环原型（隔离目录，一次性）
│   ├── index.html    # 单文件、零依赖、离线可用的选品台原型
│   └── README.md     # 原型说明与隔离约定
└── README.md         # 本文件
```

## 当前状态

- ✅ 第一版原型（`prototype-v1/`）：模块库 + 拖拽落地 + 实时预览 + 主题换肤 + 交互变体 + 导出配置单
- ⏳ 正式版：待原型验证手感后另起目录开发
- ⏳ MCP 集成：后续把配置单变成 AI 可直接调用的资源

## 隔离约定

`prototype-v1/` 是一次性原型，只用于验证手感，不做长期演进。正式版会另起目录，从原型里"提炼结论"（模块分类法、schema 设计、交互手感），而不是继承代码。

## 设计借鉴

- 导出 schema 对齐 Automattic `site-spec` 的"页树 + 事实字段"结构
- 页面渲染模型对齐 Flexilte `LayoutConfig` 的递归树（模块 + 变体 + 顺序）
- 模块素材可复用 MIT 协议的 shadcn/ui、Aceternity、Flowbite 区块
- 主题层使用 CSS 变量，预埋 W3C Design Tokens 对接点
